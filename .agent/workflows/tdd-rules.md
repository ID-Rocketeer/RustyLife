---
description: Test-Driven Development (TDD) rules for this environment
---

In this environment, you MUST follow strict Test-Driven Development (TDD) principles before writing or modifying any implementation code.

Before changing code, you MUST always ask yourself: "How do I test this?"

1. Write the tests FIRST. 
2. Run the tests to prove they fail (or in some cases, pass incorrectly).
3. Then, and only then, write the actual implementation code.
4. Run the tests again to prove your implementation works.
5. Wait for user input before committing new code.
6. Remind the user about uncommitted work when starting work on a new phase/task. Do not leave the current task in an uncommitted state without explicit permission to pivot.

Do not bypass this process. Do not write the implementation first and add the tests later.
